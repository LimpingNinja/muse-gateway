## Native discovery

For a resolved Q host of `runtime.<api-region>.kiro.dev`, startup and TTL refresh share one catalog helper. It sends:

```text
POST https://management.<resolved-api-region>.kiro.dev/
Content-Type: application/x-amz-json-1.0
x-amz-target: AmazonCodeWhispererService.ListAvailableModels
Authorization: Bearer <existing account access token>

{"origin":"AI_EDITOR","profileArn":"<only when already available>"}
```

There are no duplicated query parameters. The region comes from the already-resolved `q_host`, not the SSO refresh region. Existing account token retrieval, retry/refresh logic, user-agent headers, inference host, and MCP host remain unchanged. Legacy Q hosts retain their existing `GET <q_host>/ListAvailableModels` request and Desktop-only profile query behavior.

Every record must be an object with a nonblank string `modelId`; duplicates, malformed JSON, an empty/missing/non-list catalog, and non-200 responses fail discovery. Model records retain all metadata, including token limits and additional request schemas. Initialization logs the existing fallback warning and loads upstream `FALLBACK_MODELS`. A failed TTL refresh logs a warning and leaves the prior model cache and timestamp intact.

### Pagination limitation

The inspected public PR request and tests do not establish a management pagination request schema. This patch deliberately sends neither guessed `maxResults` nor guessed continuation requests. Its catalog limit is one terminal page. Any nonempty or malformed `nextToken` produces an explicit incomplete-catalog error; the first page is never installed as a complete catalog. Missing, null, or empty `nextToken` is accepted. Multi-page native discovery remains unsupported until a public schema or observed request establishes its contract.

## Static Kiro-side Python configuration alternative

This is an alternative to the discovery patch, not a Muse-side override. [models.py.example](models.py.example) contains the 22 model IDs captured once from the authenticated working Kiro endpoint; its header records the capture time. Kiro Gateway does not load a standalone models YAML/JSON file. Its supported configuration is the Python `FALLBACK_MODELS` declaration in `kiro/config.py`.

Copy only the example's `FALLBACK_MODELS = [...]` declaration into the existing declaration in your Kiro checkout's `kiro/config.py`. **Do not replace that whole configuration file** or merely drop the example next to it: other required settings must remain intact. No new loader or Muse model override is needed.

On the unpatched runtime-host base, this static list is used at startup and refresh. With the discovery patch, it is the failure fallback. Restart your Kiro service after editing its Python configuration. Muse continues autodiscovering through Kiro's `/v1/models`; to curate the Muse menu, use `MUSE_GATEWAY_MODELS` with exact `kiro/<model-id>` IDs (a filter, never entitlement). `auto-kiro` in the snapshot is Kiro's existing alias for `auto`.

The snapshot records names, not tested entitlements or capacities, and will become stale as Kiro adds or removes models. During verification, the native management API returned 21 models, while the working legacy-Q service returned 22: management omitted the older `claude-sonnet-4`. Repeating the source PR's exact request shape produced the same difference. The patch uses the management API's authoritative response; it does not silently merge older snapshot entries into live discovery.

## Applying the patch

Apply this patch only to an unmodified checkout of the pinned BASE, not over another local discovery workaround:

```sh
git clone https://github.com/jwadow/kiro-gateway.git kiro-gateway
cd kiro-gateway
git checkout a5292ca04c7c6231e0b47673ac3f981f5a706e1e
git apply --check /absolute/path/to/muse-gateway/errata/kiro-model-discovery.patch
git apply /absolute/path/to/muse-gateway/errata/kiro-model-discovery.patch
python -m pytest tests/unit/test_account_manager.py tests/unit/test_http_client.py -q --tb=short
```

Run the test command in that checkout's existing environment with its requirements installed. The patch was developed in a fresh upstream clone; it has not been applied to the user's working Kiro installation. No server, test service, or credential mutation was needed to build it.

## Verification and gaps

The patch adds three focused tests to the existing upstream files:

- Native discovery populates the catalog at startup and refreshes it after TTL expiry, using the resolved API region and preserving metadata.
- An incomplete catalog triggers the existing startup fallback and cannot replace a previously valid cache on refresh.
- Discovery headers survive an authentication retry without leaking into a later inference request.

Existing upstream tests are unchanged. The patch does not add a login/region/status-code test matrix.

The maintained tests are offline protocol/regression checks, not live entitlement verification. A separate read-only catalog probe confirmed the native management request succeeds for the current Google/social login; its catalog difference is documented above. SSO accounts have not been live-tested. The patch has not replaced the user's working legacy-Q discovery workaround. Full suites, inference probes, and test services were not run. Upstream has no configured linter/type-checker gate in the inspected root/CI metadata.
